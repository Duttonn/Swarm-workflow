# Swarm size 1 to 20 on one free model, secure-server brief (2026-09-15)

Brief: `prompts/18-secure-server.json`, one Node stdlib HTTP server, 20 roles (16 owners + 4
reviewers), 19 fixed tests (7 functional, 12 security). Same judge for every row. Provider:
NVIDIA NIM free tier, `nvidia/nemotron-3-super-120b-a12b`, through the `nim` runner
(`adws/adw_modules/runners/nim.py`), $0 by the provider's accounting. Sweep script:
`bench/scale_sweep.sh`; table: `bench/sweep_report.py`.

Totals for the night: 872 completions, 24.8M tokens, 180 in-band 503 lines, 39 HTTP 429.

Three causes, all in the runner, all fixed before round 2:

1. **Rate limit.** NIM's free tier is about 40 requests a minute per key. Five owners each
   cycling a tool call every few seconds exceed that alone, so the 429s are self-inflicted;
   whether the 503s are too is not known (they say "overloaded", not "too many"). Fix: one process-wide throttle (`MIN_INTERVAL` 1.6 s between request
   starts, shared by every agent thread), 429 backoff of 20/60/180 s honouring `Retry-After`,
   and `SWARM_MAX_PARALLEL=3`.
2. **Tool-set oscillation.** With an overwrite-only `write_file`, the solo agent wrote a 14,168
   byte body, then a 1,280 byte `htmlview` block over it, read the file back, saw only the
   block, wrote the body again, wrote the block over it again: 60 steps, 20 minutes, 1,280
   bytes shipped. The model never set `append`. Fix: `edit_file` (exact-once replace, the
   tool models are trained on), `read_file` returns the whole file (the 8 KB cap made a
   20 KB file look cut off), and an overwrite that shrinks a file now answers
   `REPLACED ...: the previous N bytes are gone`.
3. **In-band errors.** An overloaded backend comes back as HTTP 200 with a single
   `{"error":{"code":503}}` data line; the first prototype read that as an empty reply after
   30 good steps. Fix: raise, retry 5/15/45 s.

What round 1 still says, with those caveats: more agents scored more (4 -> 11 -> 18 of 19
from size 2 to 10) even with half the owners lost to rate limits, and the size-10 board
carries the first cross-block defect reports this harness has produced. Whether the trend
survives a fair run is what round 2 is for.

soloist does not.

### The provider's budget, read from its forum (2026-09-15)

- 40 requests a minute per account, "dependent on model, use-case and the amount of current
  overall traffic"; no increase is granted on the free tier and no `Retry-After` or
  `X-RateLimit-*` header is returned (forums.developer.nvidia.com threads 368420, 377111).
  Measured here: one throttled agent at 37 RPM still drew two 429s in a minute, so the runner
  now spaces requests 2.5 s apart process-wide (24 RPM) and backs off 20/60/180 s on 429.
- **1,000 API credits per personal-email account** (5,000 with a business email, via
  Profile > Request More); exhaustion answers with an authorization error, not a 429
  (thread 306633). Round 1 alone made 872 completions. If a credit is a request, the
  account is close to its ceiling and the ladder below will stop on a 401. Not verifiable
  from the API; the balance is on build.nvidia.com under the profile.

### Why every nemotron run scores 18/19, and it is not reasoning

Solo (round 2), size 2 (round 2) and size 10 (round 1) all fail the same test,
`test_sec_stored_xss_escaped`, and the shipped `escapeHtml` is the same in each:

```js
.replace(/&/g, '&').replace(/</g, '<').replace(/>/g, '>').replace(/"/g, '"')
```

Characters mapped to themselves. Probe (`scratchpad/nim/probe_entities.py`): asked for a file
whose content is exactly `.replace(/&/g,'&amp;').replace(/</g,'&lt;')`, the tool-call arguments
arrive on the wire as `'&'` and `'<'`. Asked again with one sentence of warning that entities
tend to come out decoded, the same model sends `&amp;` and `&lt;` intact. So it is the model
rendering entities as it writes, not the transport, and a caution now rides on `write_file`
and `edit_file`. Two consequences for the experiment:

- the 18/19 plateau was a shared defect of every configuration, solo included, so no size
  comparison so far measures reasoning or coordination at the margin that matters;
- the size-10 reviewers did read the defect correctly ("maps characters to themselves"),
  which is the one thing a second pair of eyes added, and no writer could act on it.

### To rerun the ladder on a provider that answers

The runner is OpenAI-compatible; only the base URL, the key and the model change:

```bash
NVIDIA_BASE_URL=https://<endpoint>/v1 NVIDIA_API_KEY=<key> SWARM_RUNNER=nim SWARM_MODEL=<model> SWARM_CALL_TIMEOUT=1500 SWARM_MAX_PARALLEL=3   bash work/queue-logs/chain.sh          # solo, control 1 2 5 10 20, treatment 1 2 5 10 20
python bench/sweep_report.py work/queue-logs/sweep-nim-control.txt work/queue-logs/sweep-nim-treatment.txt   --solo work/measured/<spec-model>/<stamp>/solo-summary.json
```

`bench/nim_models.py <model>` first: it says in a minute whether the model answers and calls
tools on that endpoint, and `SWARM_NIM_MIN_INTERVAL` sets the floor of the request spacing.
